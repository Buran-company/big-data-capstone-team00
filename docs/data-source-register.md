| Field | Source 1: Game Events | Source 2: In-App Purchases | Source 3: User Profiles |
| :--- | :--- | :--- | :--- |
| Producer & Purpose | Game client application (Android/iOS); tracks player actions, progress, and performance metrics for monitoring and product analysis | App stores (Google Play & App Store webhooks); records monetization events, subscriptions, and financial transactions | Backend relational database (PostgreSQL); stores user account details |
| Record Grain | One player action/event (for example, click, level completion, client error, death) with an exact timestamp and player_id | One successful, failed, or refunded purchase transaction with a unique purchase_id | One row per user account with user_id |
| Structure & Format | Semi-structured JSON strings parsed into typed columns (TIMESTAMPZ, BIGINT, TEXT) | Structured JSON payloads containing transaction metadata, user tokens, and status enums | Structured rows with SQL data types (BIGINT, VARCHAR, TIMESTAMP) |
| Arrival & Scale | Continuous event stream; up to 5,000 events/sec peak rate; ~50 GB raw daily volume; retention 1 year; late-arrival handling required | Webhook batch events; triggered upon user purchase actions; average peak volume; permanent financial retention | Daily incremental snapshots (backup); small daily volume; historical updates |
| Quality Risks | Missing device IDs, duplicate events due to client retries, out-of-order event delivery, schema drift during game updates | Delayed webhooks from app stores, duplicated purchase notifications, currency conversion discrepancies, missing transaction IDs | Null values in optional profile fields, duplicate email registrations, conflicting status updates |
| Sensitivity & Ownership | Data Owner: Client Engineering Team. Classification: Restricted. Contains IP addresses and device identifiers, require pseudonymization |Data Owner: Finance & Monetization Team. Classification: Confidentially Restricted. Contains payment tokens and purchase histories | Data Owner: Backend Engineering Team. Classification: Restricted Personal Data. Contains emails and account credentials |
| Acquisition Method | API Gateway landing directly into a Kafka topic | Secure Webhook listener endpoint | Daily automated database snapshot into the raw cloud storage |
